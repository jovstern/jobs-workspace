<objective>
Make sure contact details and links never leave the machine: one shared pure function removes
email addresses, phone numbers, street addresses and links (D-07, D-18), and the server applies
it to every fit request before the model is called, even if the browser sent raw text.

Purpose: D-07 has to hold from the first real model call, including when a client misbehaves.
The same function is used by the paste form in plan 01-08, so what the user sees, what is saved
and what is sent are the same string.

Output: `redactContactDetails` in the shared package with fixture tests, and
`prepareResumeForModel` on the server wired into `POST /api/fit`.
</objective>

## Flagged assumptions

- **Removal is pattern-based and incomplete by design.** Addresses with no street-type word, non-Latin formats, numbers written as words and personal sites on unknown hosts without a scheme are not recognised. The privacy note (plan 01-11) says "where we can recognise them", and the paste form (plan 01-08) shows the user the text before it is saved so they can remove anything else. If the user wants stricter removal, that is a new decision.
