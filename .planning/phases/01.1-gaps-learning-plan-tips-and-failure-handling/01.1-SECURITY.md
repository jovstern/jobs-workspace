# Phase 01.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

The register was written at plan time (all nine plans carry a threat model). At ASVS level 1 each mitigation was checked by searching the code and tests for it; the full test gates (`npm run check`, server check, `npm run e2e`) passed on the same commit.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model to server | Plans and tips are untrusted text produced from an untrusted resume |
| Resume to model | Text in the resume may try to steer what the model writes |
| Model text to page | Steps, why texts and quotes come from a model that read an untrusted resume |
| Browser storage to page | A stored analysis may be old, duplicated or edited by hand |
| Model to server | Tips, keywords and plan text are untrusted and may echo or obey text planted in the resume |
| Server to browser | Whatever passes these checks is stored in the browser and shown to the user |
| Browser storage to app | Stored values come from an earlier session or code version and may be damaged or edited by hand |
| App to browser storage | Writes can fail (quota, private mode) at any time |
| Provider to server | Error bodies and messages from Google may echo the prompt, the resume or the key |
| Server to browser | Error envelopes cross to the page and may be shown to the user |
| Model text to page | Tip advice, quotes and keywords come from a model that read an untrusted resume |
| Browser storage to page | A stored analysis may be old or edited by hand |
| Developer machine to Gemini API | Real, paid requests with the user's key |
| Script output to the repository | Results are committed under `.planning/` |
| Server to page | Error envelopes carry a message string the page did not write |
| User's click to paid call | Each fit request costs money and counts against the app's limiter |
| Thrown error to response | Anything thrown inside the server may carry request, resume or provider text |
