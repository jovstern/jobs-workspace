## Phase Goal

**As a** job seeker, **I want to** see what is missing and what to learn next, and to recover cleanly when the AI or my saved data fails, **so that** every fit check leaves me with a next step.

<objective>
Tracer, server half. One fit check now returns a learning plan for every gap, through every
server layer that this phase changes: the shared contract, the prompt and the schema shown to
Google, the AI client seam, the fit pipeline, the stand-in model and the route.

Purpose: FIT-06 starts here, and so does the phase's main architectural claim: the ratings are
the product and advice is extra, so advice is parsed leniently and can never cost the user a paid
result. Proving that end to end on the first commit is cheaper than finding it after the UI exists.

Output: `advice` widened from `null` to "advice or null" with no storage migration (D-E08); a
strict wire schema and a lenient parse schema; `buildAdvice`; a stand-in that answers with plans
and tailoring; larger output cap and deadline for the larger answer; the API coverage note.

Scope notes:
- `tailoring` is always `null` in this plan's responses. That is one of the contract's defined
  states ("the tips part was unusable") and is safe: no unverified tip can reach a user. Plan
  01.1-03 adds the verified tips and filtered keywords, and per-step leniency and link rejection.
- This plan has 14 files because a tracer changes one small thing per layer.
- Decisions made here under "Claude's Discretion": advice comes in the same model call as the
  ratings (the split rule applies only if a measured p90 goes above about 15 seconds; plan
  01.1-07 offers that measurement); thinking stays LOW; output cap 8192; deadline 45000 ms.
</objective>

## Flagged assumptions

- **Advice size and latency are estimates** (research A2, A3). Cap 8192 and deadline 45000 are
  safe defaults chosen without a paid call. Only plan 01.1-07, if the user approves it, measures them.
- **Google has not been shown this schema** (research A4). Every test here uses the stand-in,
  which accepts anything. A rejected schema would break every real fit check while all gates stay
  green; plan 01.1-07 offers the one-call check.
- **A plan with one surviving step is kept** (research A6; the approved UI contract renders 1 to
  4 steps). If the user prefers to drop such a plan, the change is the minimum of `steps` in
  `learningPlanSchema`.
- **Job summary lines are added to the prompt** so "why it matters for this job" has more than
  one requirement line to work from. Seed postings are trusted text; the stand-in ignores the lines.
