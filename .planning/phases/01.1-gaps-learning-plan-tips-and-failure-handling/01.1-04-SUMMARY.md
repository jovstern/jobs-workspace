# Phase 01.1 Plan 04: Saved data that fails safe Summary

**Corrupt, half-corrupt, newer and unwritable saved data is now migrated or set aside by one `createGuardedStorage` helper, announced in a notice at the top of the page, and never blocks the page or a completed fit check.**

- **Duration:** about 8 min
- **Started:** 2026-10-12T11:05:41Z
- **Completed:** 2026-10-12T11:13:00Z
- **Tasks:** 3 (one tracer, two TDD)
- **Files:** 14 (9 created, 5 modified)

## Accomplishments

- **Tracer (Task 1):** `jw:analyses` holding `{broken`, then a reload, gives a caution alert above the header, the raw text copied to `jw:analyses:corrupt:{ISO time}`, the original key gone, a working paste form and job list, and a Dismiss that moves focus to the `h1`. Proven in a real browser with zero `/api/fit` requests.
- **Versions and per-entry drop (Task 2):** newer versions are set aside as `newer`; older versions run `migrations[v]` step by step and are written back at once; a missing or throwing step is `unreadable`; fit checks are validated one by one (key must equal `jobId`), the bad ones go to a copy in the same `{ state, version }` envelope and the cleaned value is written back so a second load reports nothing. Three copies per store are kept, same-instant copies get `-1`, `-2`. The resume store uses the same helper.
- **Write failures and unkept copies (Task 3):** `setItem` and `removeItem` never throw; a failed save reports `write_failed` once per store and the state stays in memory. A failed copy gives up older copies once and retries; if it still fails the incident says `copyKept: false`, the original is left in place, and none of the six "could not be kept" sentences contain "A copy is kept in this browser."
- All eleven UI-SPEC storage sentences are pinned by tests; the notice has no download, restore, export or erase control or wording.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The `mb-6` spacing sits inside `StorageNotice`, not in an App wrapper**
- **Found during:** Task 1
- **Issue:** The plan asked for `StorageNotice` inside an `mb-6` wrapper in `App`. That wrapper would be an empty block with a bottom margin when there is no incident, adding 1.5rem above the header on every normal page and breaking "with no incident the notice is not rendered at all".
- **Fix:** `StorageNotice` returns `null` for an empty list and otherwise wraps the notice in `mb-6` itself; `App` renders it directly as the first child.
- **Files modified:** `src/features/storage-notice/StorageNotice.tsx`, `src/App.tsx`
- **Commit:** 6458d1d

**2. [Rule 1 - Bug] An existing fit-store test changed meaning**
- **Found during:** Task 2
- **Issue:** The Task 1 version of "a stored entry of the wrong shape" expected an `unreadable` set-aside of the whole value. With per-entry validation, one bad entry in an otherwise valid `byJobId` is correctly a `partial` drop. The whole-value cases are covered by the new table test (missing `byJobId`, array, string).
- **Fix:** Test renamed and its expectation changed to a `partial` incident with `dropped: 1` and an envelope copy.
- **Files modified:** `src/features/fit-analysis/fit-store.test.ts`
- **Commit:** 6a817c6

**3. [Rule 2 - Missing critical] A failed write-back of the cleaned or migrated value reports `write_failed`**
- **Found during:** Task 3
- **Issue:** The plan only named `setItem` for `write_failed`; the immediate write-back after a migration or per-entry drop is also a write, and swallowing its failure silently would hide that the same entries come back next load.
- **Fix:** That write reports `write_failed` like any other.
- **Files modified:** `src/lib/guarded-storage.ts`
- **Commit:** 464bc68

**Total deviations:** 3 auto-fixed (2 bug, 1 missing critical). **Impact:** none on scope or contracts.
