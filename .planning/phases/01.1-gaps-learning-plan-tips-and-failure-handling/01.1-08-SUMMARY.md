# Phase 01.1 Plan 08: Failure messages, Try again and staged progress Summary

**A failed fit check now says why in one fixed sentence per code, offers Try again only when the envelope marks it retryable, names a stopped app server and a browser timeout, and a running check shows staged progress text in a single status region.**

## Performance

- **Tasks:** 3 of 3, each with a RED test commit and a GREEN feat commit (six commits)
- **Gates at the end:** `npm run check` exit 0, `npm --prefix server run check` exit 0 (467 server tests), `npm run e2e` 17 passed
- **Duration:** not timed separately (the start time was lost to a context reset)

## Accomplishments

- `describeFitError` maps any failure to a message, a retry flag and an action tag. The sentence is looked up by exact code (browser-only table first, then the shared table, then the generic retryable or reload sentence by flag). The server message never reaches the page.
- `apiRequest` raises `server_unreachable` for a fetch rejection and for a response with no valid envelope at status 500 and above, and `request_timeout` for a browser timeout. The browser timeout default is 60 seconds.
- `FitErrorNotice` renders the heading "Could not check your fit", the sentence as plain text, and Try again only for a retryable failure. Try again re-sends the same variables once and moves focus predictably.
- `progressLine` and `FitProgress` show "Reading your resume", "Comparing it with each requirement" at 4 seconds, "Writing your learning plan and tips" at 10 seconds and the long-wait line from 30 seconds. `FIT_REASSURANCE` is the single home of "Usually 10 to 20 seconds."
- `FitPanel` has exactly one `role="status"` region, always mounted, holding the stage line while a check runs and the completion line afterwards.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Focus was lost after Try again on the primary button**
- **Found during:** Task 1 GREEN
- **Issue:** Only the header Check again button carried the focus ref, so after Try again from a state with no result, Check my fit had no focus.
- **Fix:** Added `ref={setActionButton}` to the primary Check my fit button and a `holdFocus()` helper that sets the pending-focus flag only when there is no result view yet.
- **Files modified:** src/features/fit-analysis/FitPanel.tsx
- **Commit:** 61bdd87

**2. [Rule 1 - Bug] Timeout detection failed under jsdom**
- **Found during:** Task 2 GREEN
- **Issue:** A `DOMException` is not `instanceof Error` in jsdom, so a `TimeoutError` fell through to `server_unreachable`.
- **Fix:** Replaced the instanceof check with a duck-typed check on the error name (`isTimeoutError`).
- **Files modified:** src/lib/api.ts
- **Commit:** df44e27
