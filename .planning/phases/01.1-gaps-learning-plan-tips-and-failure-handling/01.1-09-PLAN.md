## Phase Goal

**As a** job seeker, **I want to** see what is missing and what to learn next, and to recover cleanly when the AI or my saved data fails, **so that** every fit check leaves me with a next step.

<objective>
The failure contract that the server and the browser share: what each failure is called, which
HTTP status and retry flag it carries, and the one sentence the user reads for it. Today the
server has nine codes and one generic sentence for all of them but `ai_not_configured`. After
this plan there are eighteen codes, each with a status, a retry flag and a fixed sentence in one
shared table, and a pure rule that turns a failure diagnostic into a code.

Purpose: FIT-11 and the server side of review finding WR-06 (a refused page address gets its own
sentence; a failure that a retry cannot fix is flagged as such). Plan 01.1-05 makes the AI client
raise these codes; plan 01.1-08 makes the page word them.

Output: nine new codes, `ERROR_MESSAGES` and the two generic sentences in `shared/src/error.ts`;
status and flag for every code in `server/src/http/errors.ts`, whose messages now come from the
shared table; the pure `failureToErrorCode`; the refused-origin and limiter sentences proven over
HTTP.

Why this is its own plan (revision of 2026-10-12, scope): it was the first half of plan 01.1-05,
whose 15 files were over the per-plan file budget. The contract shares no file with the plans of
waves 1 and 2 and needs nothing they build, so it runs in wave 1 beside plan 01.1-01. Plan
01.1-05 keeps the AI client, the diagnostics, the stand-in and the tests that pin what a failed
call answers.

Decisions made here under "Claude's Discretion" (the exact set of codes): the eleven `ai_*` codes
in the tables below, within the table in `01.1-UI-SPEC.md` "Errors". The two browser-only codes
(`server_unreachable`, `request_timeout`) are plan 01.1-08. The browser's fit panel is unchanged by
this plan: it shows its own Phase 1 sentences and never the server's message, so the browser
gates stay green.
</objective>
