# Phase 01.1 Plan 05: Server failure codes Summary

**Every failed Gemini call now leaves `POST /api/fit` as the typed code that names its cause (rate limit, busy, timeout, unreachable, refused key, billing, declined, cut off, unusable, generic), with the status, retry flag and fixed sentence from plan 09, and a missed deadline is finally told apart from a browser that left.**

## Performance

- **Duration:** 11 min
- **Tasks:** 3 (1 tracer, 2 TDD)
- **Files modified:** 8 (all under `server/src/`)

## Accomplishments

- The AI client has one `fail(diagnostic)` helper used by every failure path; it hands the closed diagnostic to `onFailure` and throws `AppError(failureToErrorCode(diagnostic))`. The tracer slice (`http_429` to 429 `ai_rate_limited` with Google's sentence) moved the other four existing scenarios (`http_503`, `blocked`, `truncated`, `garbage`) with it.
- The deadline signal is kept (`const deadline = AbortSignal.timeout(deadlineMs)`); in the `catch`, `deadline.aborted && !request.signal.aborted` reports `{ httpStatus: null, category: 'timeout', errorClass: 'TimeoutError' }`. A caller that left stays `ai_failed` with category `aborted`.
- Finish reasons are split with two named sets built from the SDK's `FinishReason` members: `MAX_TOKENS` and `CONTINUATION` mean cut off; `SAFETY`, `PROHIBITED_CONTENT`, `BLOCKLIST`, `SPII`, `RECITATION`, `LANGUAGE` and `OTHER` mean declined; a missing reason means empty; anything else is unknown. Empty ratings need no new code: the existing strict `min(ids.length)` parse already reports `schema_mismatch`, which maps to `ai_invalid_output`.
- `diagnose.ts` gained a second fixed-token search (`API_KEY_INVALID`), checked after `FAILED_PRECONDITION`; a 400 naming it is category `UNAUTHENTICATED`. Nothing is copied from the message.
- The stand-in gained `http_403`, `http_402`, `http_400_billing`, `http_400_key`, `finish_safety`, `finish_unexpected`, `empty`, `no_candidate`, `empty_ratings`, a `slow` scenario that ends in the same valid answer as `ok`, and `startFakeGemini({ slowDelayMs })`.
- `routes.test.ts` holds one `FAILURE_TABLE` (14 scenarios, status, code, retry flag, message equals `ERROR_MESSAGES[code]`, one upstream request each), checks that no body holds provider wording, the task line or a resume sentence, covers an unreachable (closed) stand-in as `ai_network`, and pins Google's 429 as header-less and worded differently from `too_many_requests`.
