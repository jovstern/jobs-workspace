### WR-03: A partly unreadable store was rewritten even when no copy of the dropped entries was kept

**Files modified:** `src/lib/guarded-storage.ts`, `src/lib/guarded-storage.test.ts`, `src/features/storage-notice/incident-line.ts`, `src/features/storage-notice/incident-line.test.ts`
**Commit:** 6a329ed
**Applied fix:** In `getItem`, the cleaned value (migration or dropped entries) is written back only when the dropped entries were copied, or when nothing was dropped. When the copy fails, the original stays in place. The `partial` notice for `copyKept === false` now reads "... A copy could not be kept, and the unreadable one(s) will be replaced the next time you save." This changes a notice sentence that UI-SPEC row "Some fit checks dropped, copy could not be kept" had decided; the SPEC document was not edited. The existing copy-failure test now asserts the original is unchanged. Requires human verification: logic change plus a user-visible wording change.

### WR-04: Rating quotes were stored with no length bound

**Files modified:** `shared/src/fit.ts`, `server/src/fit/analyze.ts`, `server/src/fit/analyze.test.ts`
**Commit:** 2443bdd
**Applied fix:** Added `RATING_QUOTE_MAX_CHARS = 600` (same value as `TIP_QUOTE_MAX_CHARS`) in shared. `settle` now withdraws a rating whose quote is longer than that, exactly like an unverifiable quote (not evidenced, no quote, no rationale, `quoteRejected: true`). The cap is applied on the server only and is not a `.max` on `ratedRequirementSchema.quote`, which is the option the review offered to avoid making already saved results fail to load and be set aside. Two tests were added: an over-length quote that occurs in the resume is withdrawn, and a quote exactly at the bound is kept. Requires human verification: logic change.
